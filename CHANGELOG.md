# Changelog

## Unreleased

### Fixed

- **Normalized output is now always valid SDL (audit criticals 1).** The compiler's output could fail its own schema: the normalizer fabricated `product.personas: []` and `artifacts.generate: []` against `minItems: 1` constraints, and emitted `railway` runtimes and (for `java-spring`) a `hibernate` ORM that were absent from the schema enums. The two `minItems` constraints are relaxed (empty arrays are valid), `railway` is added to all three `deployment.runtime` enums, `hibernate` to the ORM enum, and `CLOUD_RUNTIME_MAP`/`FRAMEWORK_ORM_MAP` are now typed against the enum unions so drift is a compile error. A new normative invariant — `validate(normalize(validInput).document)` passes — is stated in the spec and enforced across every example and template by `audit-conformance.test.ts`.
- **A missing import can no longer compile successfully (audit critical 2).** `compileWithImports()` only failed when resolution errors coincided with an *empty* merged document; a complete root with a missing import returned `success: true`. Any resolution error now fails compilation, per the new normative statement in the spec's import constraints.
- **The resolver now implements the spec's import semantics (audit high 3).** Nested import paths resolve relative to the declaring module (the resolver joins module directories, so `readFile` still receives root-relative paths); cycle detection uses a resolution stack instead of a never-unwound global visited set, so diamond dependencies (root → A → shared, root → B → shared) load once instead of falsely erroring as circular; and the spec's identity-keyed arrays (`domain.entities[]`, `integrations.custom[]`, `features[]`, keyed by `name`) merge by identity — a duplicate emits the previously never-emitted `duplicate-array-item` warning and the later module's entry replaces the earlier one.
- **`compliance-checklist` is now requestable from valid SDL (audit high 4).** The artifact was in the TypeScript union, the generator registry, and the canonical contract, but missing from the schema enum, so requesting it failed with `INVALID_ENUM`. The enum now carries all 13 artifact types, a conformance test asserts enum ⇔ registry equality, and `reference/ai-authoring.md` no longer claims unknown values are "not validation errors" (they are).
- **v1.1/v1.2 boundary contradictions resolved (audit high 5).** Import Forms B and C are declared v1.1 amendments (they ship under `sdlVersion: "1.1"`); the spec's "(added in v1.2)" labels are corrected, and `spec/ROADMAP.md`'s current-state table and §1/§2 plans now match `reference/section-support.md` — `contracts`, `domain`, `slos`, `compliance`, and `resilience` are `partial` (consumed by generators) rather than planned-for-v1.2.
- **Type/schema/prose drift (audit high 6).** `DomainField` now exposes the schema's full field surface (`nullable`, `primaryKey`, `foreignKey`, `unique`, `generated`, `default`, `enum`, `maxLength`, `precision`, `scale`, `description`, `onUpdate`); `DeploymentRuntime` uses closed unions matching the schema enums instead of `string`; placeholder sections (`costs`, `backupDr`, `design`) carry open index signatures matching their permissive schemas; the stale package-internal `packages/sdl/src/schema/sdl-v1.1.d.ts` (root `environments`, `hybrid` style, lowercase stages, array `slos`) is deleted — `schema/sdl-v1.1.d.ts` is the one declaration mirror, and it is refreshed; spec rule 18's "field absent" note is updated.
- **Spec rules that were impossible as written (audit medium 8).** Rule 30 no longer references a nonexistent `resilience.retryPolicy[]` array (it is a single object); warning rules 7, 8, and 12 no longer reference a nonexistent `production` stage (stages are `MVP`/`Growth`/`Enterprise`); the "Complete specification (production-grade)" version-strategy claim is replaced with an accurate amendment list.

### Added

- **SEM-015 / `ARCHITECTURE_EMPTY`** — `architecture` must declare at least one project (any category) or one `architecture.services` entry, closing the gap where `reference/ai-authoring.md` required "at least one project" but `projects: {}` compiled. Active rule count goes from 27 to 28 (14 enforced as `SEM-*`).
- **Canonical-location normalization (audit medium 7).** `techDebt` entries are mirrored into canonical `technicalDebt` (deduplicated by `id`, idempotent), and shorthand compliance declarations (`nonFunctional.compliance.frameworks`, `constraints.compliance`) are lifted into canonical root `compliance.frameworks[]` when it is absent — so the `coding-rules` and `compliance-checklist` generators read one location. Reconciliation rules documented in `reference/canonical-contract.md` → *Canonical Locations for Overlapping Declarations*.
- `audit-conformance.test.ts` — 21 conformance tests: normalized-validity round-trip over the full example/template corpus, import-failure compilation, declaring-module-relative paths, diamond vs. genuine cycles, identity-keyed merging, artifact enum ⇔ registry equality, SEM-015, alias normalization, and normalize-idempotence.

- **`deployment.infrastructure.iac: cloudformation` was rejected on every cloud, including AWS.** The schema's `allOf` branch was `{"not": {}}` (unsatisfiable) with an `if` that never inspected `deployment.cloud`, making the enum value unusable. It now correctly requires `cloud: aws`. No test covered the positive case; `examples/conformance/valid/aws-cloudformation.yaml` is the new regression guard, paired with the existing negative `examples/single-file/azure-cloudformation.yaml`.
- **`solution.name` rejected dots.** The pattern `^[a-zA-Z0-9\s\-]+$` failed on domain-style names, so the project's own `examples/single-file/sdlang-com.sdl.yaml` ("SDLang.com") did not validate. Widened to `^[a-zA-Z0-9\s\-_.]+$` and documented in `reference/canonical-contract.md` → *Constrained Scalar Fields*, which previously listed no charset constraint at all.
- **`imports` was rejected by the JSON schema.** The root object is `additionalProperties: false` and did not declare `imports`, despite a full normative spec section for it. It worked only because the resolver strips the key before validation — meaning `compile()` failed on any modular root file, and anyone validating raw SDL against the published schema rejected every modular document. `imports` is now declared in the schema and on `SDLDocument`.
- **`coding-rules` and `coding-rules-enforcement` were unreachable through `generate()`.** Both are valid `artifacts.generate[]` values with entries in `REGISTRY_TIER_MAP`, but were missing from `GENERATOR_MAP`, so `generate()` returned `null`. Registry now covers all 13 declared artifact types (was 11).
- `packages/sdl/package.json` `files` omitted `dist-esm` while `exports.import` pointed into it, so ESM consumers of the published package resolved a missing entry point.
- Spec corrections: the *Resilience* example used array shapes for four sub-keys that the schema defines as objects and included `bulkhead`/`fallback` keys the schema rejects (5 validation errors); a root-level `mobile:` section was documented but does not exist; rule 17 cited `deployment.ciCd.iac` instead of `deployment.infrastructure.iac`.
- Count and status drift across spec, README, and reference docs: "Reference Integrity (7 rules)" (6 active), "14 semantic rules" (13 — SEM-006 is a tombstone, now stated), "12 registry-backed artifact types" (13), warning rules presented as shipped when 7 of 11 are unimplemented, and a normalization table in `error-codes.md` that had drifted from the one in `normalization-defaults.md`.
- `reference/error-codes.md` listed a warning code (`ADMIN_ROLE_REQUIRES_AUTH`) that the validator never emits, and documented none of the 13 `SEM-*` codes or the resolver's import-resolution codes.
- `examples/conformance/invalid/service-dependency-cycle.yaml` also tripped `PROJECT_NAME_DUPLICATE`, so it no longer isolated the rule it exists to prove.

### Changed

- **Backend framework values are now unversioned; runtime version moves to `runtimeVersion`.** `dotnet-8` was the only framework enum value carrying its version in the identifier, which would have required a schema change on every .NET release. The canonical value is `dotnet`, with an optional free-form `architecture.projects.backend[].runtimeVersion` (e.g. `"10.0"`). `dotnet-8` is accepted as a **normalized alias** — rewritten to `dotnet` + `runtimeVersion: "8.0"` with both rewrites reported as inferences — and is removed in SDL v2.0. This is the first alias SDL normalizes rather than rejects; `reference/canonical-contract.md` gains a *Normalized Aliases* section and states why it is the exception. Adding .NET 10 support is now a `runtimeVersion` value, not a contract change.
- **Generator runtime versions are centralized and refreshed.** Every version string the generators emitted was a hard-coded literal duplicated across `cicd.ts` and `coding-rules-enforcement.ts`, free to drift apart and years out of date (Node 20, Python 3.12, Go 1.22, Java 21, .NET 8, Ruby 3.3, PHP 8.3). `DEFAULT_RUNTIME_VERSION` and `RUNTIME_BASE_IMAGE` in `constants.ts` are now the single source of truth for CI setup actions, Dockerfile base images, and container tags; per-project `runtimeVersion` overrides them. Tests assert against the same table rather than restating version literals.
- `examples/single-file/` is now globbed by the test suite with an explicit negative-fixture denylist. It was an allowlist of 7 files against a directory of 13, which is how the broken `sdlang-com.sdl.yaml` shipped unnoticed.
- `schema/sdl-v1.1.schema.json` is now a byte-identical mirror of `packages/sdl/src/schema/sdl-v1.1.schema.json`, regenerated by `npm run sync:schema` on every build and enforced by `schema-mirror.test.ts`. The two files declared the same `$id` while the mirror lagged several releases behind — missing every `additionalProperties: false` hardening on `contracts`, `domain`, `compliance`, `slos`, and `resilience` — and README pointed at the stale copy as the active schema.

### Added

- `architecture.errorConventions` — solution-wide error envelope, status↔code mapping, and default retry policy. Cross-cutting architectural decision used to generate error middleware, typed SDK error classes, and OpenAPI `ErrorEnvelope` schemas. Spec section in `spec/SDL-v1.1.md`; canonical enums in `reference/canonical-contract.md`; full field surface in the JSON schema.
- `Endpoint*` and `ErrorConventions` TypeScript types mirrored into `packages/sdl/src/types.ts` and `packages/sdl/src/schema/sdl-v1.1.d.ts` (the package-internal `.d.ts` had been stale).
- **`imports[]` ergonomic forms (Form B and Form C).** Existing path entries (Form A — `sdl/services.sdl.yaml`) are unchanged. New: Form B drops the `.sdl.yaml`/`.sdl.yml` extension (`- sdl/services`); the resolver tries `.sdl.yaml` then `.sdl.yml`. Form C accepts an explicit `{ name, path }` object; `name` is reserved for future cross-module references and is currently used for diagnostics + duplicate-detection. Names should match `^[a-zA-Z][a-zA-Z0-9_-]*$` (kebab-case allowed). Forms may be mixed within one `imports[]` list. New `ImportEntry` and `NamedImport` types exported from `@sdl/core`. Spec changes in `spec/SDL-v1.1.md` § "Modular SDL and Import Semantics"; quick-reference in `reference/ai-authoring.md`. 12 new resolver tests cover the new shapes; existing multi-file showcase examples still pass through the unchanged Form A path.

### Removed

- Reverted typed `architecture.services[].endpoints[]` (PR #1, commit 2e87c30). SDL is intentionally not an API description language — per-operation contracts belong in OpenAPI / GraphQL SDL / gRPC / AsyncAPI files, referenced from `contracts.apis[]` via `x-` extension fields. The reverted PR would have introduced a homegrown OpenAPI-lite vocabulary inside SDL.

### Changed

- `reference/canonical-contract.md` authority order corrected to put `spec/SDL-v1.1.md` first (matches the spec's own claim of normative authority and `reference/schema-reference.md`'s hierarchy).
- `spec/SDL-v1.1.md` API Contracts Section rewritten to make the "inventory + external spec pointer" stance explicit; the prior text deferred richer shapes to a future version that will not arrive in SDL.
- `spec/ROADMAP.md` v1.2 plan for `contracts` updated: drops the "extension fields for endpoints" phrasing and reaffirms that per-operation detail belongs in external specs, not SDL.
- Two new validation rules for `errorConventions` (status range, retry-policy consistency); rule count goes from 25 to 27 active.
